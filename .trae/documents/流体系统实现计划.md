# 流体系统实现计划（类 Minecraft 水/岩浆）

## 一、摘要

为游戏加入类 Minecraft 的流体系统：

- **服务器权威模拟**：新增 `FluidSim`，每 4 tick（8Hz）在服务器主 tick 线程运行，水/岩浆按 8 级水位下落、扩散、衰减、反应。
- **8 级水位模型**：level 0 = 源（满格、永续），1~7 逐级变薄，水扩散 7 格、岩浆 3 格。
- **水桶/岩浆桶**：新增 bucket / water_bucket / lava_bucket 物品（纯名称字符串，不改 blocks_data.js）。持空桶对水/岩浆右键舀取，持水桶/岩浆桶对空气右键倒出源方块。
- **放置规则放宽**：普通方块可放置在液体格内（替换液体）；破坏液体变空气且不掉落物。
- **玩家游泳**：桌面客户端进入水中后减速、上浮、禁用二段跳/冲刺（岩浆仅流动，无伤害——游戏无血量框架）。
- **水×岩浆反应**：相遇生成圆石(12)；水触岩浆源生成黑曜石(170)。
- **客户端范围**：仅桌面 libGDX 客户端；Web 前端不改（忽略新增 `lv` 字段，行为与现在一致）。
- **存档**：Chunk 序列化追加 level 段，旧档无该段视为全 0（满格源），向后兼容。

## 二、当前状态分析（已核实）

| 环节 | 现状 |
|---|---|
| 方块数据 | `Chunk.tiles = int[16][16]`，WATER=32、LAVA=33 直接存 int；序列化 `\|` 分隔文本（256 值），反序列化兼容旧档 |
| 服务器权威 | `WorldCore.applyBlockAction`：break 要求非 AIR，place 要求 `current==AIR`，无液体概念；唯一逐 tick 逻辑是 `tickDrops` |
| 变更记录 | `ServerInfiniteMap.tileChanges` 为 `int[4] {x,y,oldT,newT}`，`GameServer.buildBaseStateJson` 转 `{x,y,type}` 增量广播 |
| 区块同步 | `GameServer.serializeChunk` 用 256 字节 Base64（`data` 字段，行优先 localY*16+localX） |
| 桌面客户端 | `ClientWorld` 只存 tile 字节数组；`LocalPlayer` 用 `blocks.isSolid` 判定碰撞（液体非实心可穿行）；`WorldRenderer` 整格画纹理（水纹理自带 alpha 0.72）；`GdxGame` 网络解析 chunks/tiles，`handlePlacing` 要求目标 AIR |
| 物品 | `BlockData.ITEM_TO_BLOCK` 已有 `"water"→32`、`"lava"→33`、`"obsidian"→170`、`"cobblestone"→12`；blocks_data.js 无 bucket 系列物品（故 `blocks.tileId("bucket")` 返回 -1，天然不会走方块放置路径） |
| 初始背包 | 桌面 `GdxGame.initDefaultInventory` 与服务器 `PlayerProfile.initDefaultInventory` 均为 5 个方块各 64 |

## 三、总体设计

### 3.1 水位模型（level 语义）

- `level 0` = 源（满格、永续）；`level 1~7` 流动，数值越大越薄。
- 渲染液面高度：`h = TILE * (8 - level) / 8` 像素（level 0 满格）。
- 水最大流动级别 `WATER_MAX_LEVEL = 7`；岩浆 `LAVA_MAX_LEVEL = 3`（MC：岩浆扩散距离短）。

### 3.2 流体模拟算法（FluidSim.step，双缓冲）

每一轮 step（只遍历**已加载区块**的格子）：

1. **源（level 0）**：本格永续保留（写入自身 type,0）；下方是空气 → 向下写 `(type, 0)`（满格下落）；下方是实心 → 向左右空气格扩散 `(type, 1)`。
2. **流动格（level ≥ 1）**：
   - 下方是空气 → 向下写 `(type, level)`（下落，保持级别）；
   - 下方是同种流体 → 本格停留（液体柱内）；
   - 下方是实心 → 向左右空气格扩散 `(type, min(level+1, maxLv))`；若邻居同种流体且其 level > 本格+1 → 回填 `(type, level+1)`（均平）。
   - 有支撑的流动格：若上方是同种流体（有补给）→ 停留；否则标记"待衰减"。
3. **衰减**：待衰减格本轮若收到了来自邻居/下方的补给（received 标记）→ 保留，否则消失（变空气）。→ 源头被舀走后，残余水逐格衰减干净。
4. **水×岩浆反应**：新网格中，相邻（4 向）水/岩浆对 → 岩浆格（或相遇格）变 COBBLESTONE(12)；若岩浆为源(level 0) → OBSIDIAN(170)。两侧液体清除。
5. **应用**：写入目标格时先判 `isChunkLoaded`（未加载区块视为边界不写、不触发生成）；经 `map.setTileTypeAndLevel` 写入 → 自动进 `tileChanges` 增量广播。

边界约定：世界外（ty<0 或 ty≥1024）视为实心（液体不外泄）；未加载区块的邻居读为空气、不跨块写入（邻居加载后自然续流）。

> 注：算法参数（衰减节奏、扩散步长）在实现后按用户实测的 MC 观感微调。

### 3.3 网络协议（向后兼容，Web 旧客户端自动忽略新字段）

- `chunks` 消息：新增 `"lv"` = 256 字节 level 数组 Base64（行优先 localY*16+localX，与 data 同序）。
- `tiles` 增量：每项新增 `"lv"`（该格新 level，非液体=0，缺省 0）。
- `blockAction`：不变。倒水/岩浆时客户端上报 `action:"place", item:"water"|"lava"`（服务器已有映射 32/33）；舀水上报 `action:"break"`（服务器破水不掉落物，因 water dr:null）。

### 3.4 桶交互（客户端做，背包权威在客户端）

- 右键且手持 `bucket`：目标为水 → 消耗 1 bucket、背包 +1 `water_bucket`、本地格子变空气(lv0)、上报 `break`；目标为岩浆同理（`lava_bucket`）。目标非液体 → 无操作。
- 右键且手持 `water_bucket`：目标为空气或液体 → 消耗 1、+1 `bucket`、本地格子变 WATER(lv0)、上报 `place item:"water"`。`lava_bucket` 同理。
- 普通方块右键放置：目标 `AIR || 液体` 均可放置（替换液体），本地与服务器都清 level。
- 左键破坏液体：变空气(lv0)，无掉落物（与 MC 无桶一致）。
- 初始背包追加 1 个空桶（桌面与服务器默认背包同步改，保证重连/新世界都能拿到）。

### 3.5 游泳物理（桌面 LocalPlayer.tick）

- `inWater` 判定：玩家中心格或脚底格为 WATER。
- 水中：水平位移 dx ±16 → ±8（减速）；重力 `vy += 1` → `vy += 0.5`；落速上限 16 → 6；按住空格上浮 `vy -= 1.2`（下限 -8）；禁用跳跃/二段跳/冲刺（不耗冲刺充能）。
- 出水面恢复原物理。

## 四、改动清单（按文件）

### core 模块（纯逻辑）

**1. `core/src/main/java/main/world/Chunk.java`**
- 新增常量 `OBSIDIAN = 170`。
- 新增字段 `private final int[][] fluidLevel = new int[SIZE][SIZE];`。
- 新增静态 `public static boolean isFluid(int type)`（`type == WATER || type == LAVA`）。
- 新增 `getFluidLevel(lx,ly)`（越界返回 0）、`setFluidLevel(lx,ly,lv)`（越界忽略，置 `modified=true`）。
- `setTile()`：写入非液体类型时 `fluidLevel[lx][ly] = 0`。
- `serialize()`：在 16 行 tiles 之后追加 16 行 levels（外层 localX、内层 localY，同样 `|` 分隔）。
- `deserialize()`：解析完 256 个 tile 后，若 `parts.length > 256` 则解析 256~511 为 levels（旧档无该段 → 全 0）。

**2. `core/src/main/java/main/world/InfiniteMap.java`**
- 新增 `getFluidLevel(tx,ty)`、`setFluidLevel(tx,ty,lv)`。
- 新增 `setTileTypeAndLevel(tx,ty,type,lv)`：`chunk.setTile` 后按 `isFluid(type)` 写 level（非流体强制 0）。
- 新增 `isChunkLoaded(int cx, int cy)`（`chunks.containsKey`）。
- 新增 `loadedChunkKeys()`（返回 `chunks.keySet()` 快照，供 FluidSim 遍历）。

### server 模块（权威逻辑）

**3. 新增 `server/world/FluidSim.java`**
- 常量：`FLUID_TICK_EVERY = 4`、`WATER_MAX_LEVEL = 7`、`LAVA_MAX_LEVEL = 3`、`COBBLESTONE = 12`、`OBSIDIAN = 170`。
- 构造传入 `ServerInfiniteMap`；`tick()` 内部计数每 4 次调 `step()`。
- 按 3.2 节算法实现；`tileAt(tx,ty)` 辅助函数处理世界边界与未加载区块。

**4. `server/src/main/java/server/ServerInfiniteMap.java`**
- `tileChanges` 元素由 `int[4]` 扩为 `int[6] {x, y, oldType, newType, oldLevel, newLevel}`。
- 覆写 `setTileType`：在 `super` 前读取旧 level，记录 `{x,y,oldT,newT,oldLv,newLv}`（newLv：非流体=0）。
- 覆写 `setFluidLevel`：记录纯 level 变更（oldT==newT）。
- 覆写 `setTileTypeAndLevel`：记录类型+level 变更。

**5. `server/src/main/java/server/WorldCore.java`**
- 新增字段 `private final FluidSim fluidSim;`（构造中用 `map` 创建）。
- 新增 `public void tickFluid()`（`fluidSim.tick()`）。
- `applyBlockAction`：
  - `break`：改走 `map.setTileTypeAndLevel(tileX, tileY, Chunk.AIR, 0)`（清 level）；
  - `place`：条件放宽为 `current == Chunk.AIR || Chunk.isFluid(current)`，写入改走 `map.setTileTypeAndLevel(tileX, tileY, blockType, 0)`。

**6. `server/src/main/java/server/GameServer.java`**
- tick 循环第 2 步：`world.drainTileChanges()` 之后插入 `world.tickFluid()`，再取 `world.getLastChanges()`（流体变更并入同一帧广播）。
- `buildBaseStateJson`：tiles 每项 `put("lv", change[5])`。
- `serializeChunk`：另生成 256 字节 level 数组（与 data 同序 localY*16+localX），`put("lv", Base64...)`。

**7. `server/src/main/java/server/PlayerProfile.java`**
- `initDefaultInventory`：追加 `"bucket|1"`。

### desktop 模块（libGDX 客户端）

**8. `desktop/src/main/java/client/data/BlocksData.java`**
- 新增常量 `T_WATER = 32`、`T_LAVA = 33`。
- 新增 `public boolean isFluid(int id)`（`id == T_WATER || id == T_LAVA`）。

**9. `desktop/src/main/java/client/world/ClientWorld.java`**
- 新增 `Map<String, byte[]> levels`（与 chunks 平行，存每格 level 0~7）。
- `putChunk(cx,cy,data)` 保留（lv=null）；新增 `putChunk(cx,cy,data,lv)`（lv 空 → 全 0）。
- 新增 `getLevel(tx,ty)`（区块/格缺失返回 0）。
- `applyRemoteTile(tx,ty,type)` 保留；新增 `applyRemoteTile(tx,ty,type,lv)`（非液体强制 0）。
- `setLocalTile(tx,ty,type)` 保留；新增 `setLocalTile(tx,ty,type,lv)`。
- `clear()` 同时清空 levels。

**10. `desktop/src/main/java/client/render/WorldRenderer.java`**
- 方块循环中：`type` 为流体时读 `lv = world.getLevel(tx,ty)`，用 10 参 `batch.draw(tex, sx, upY, TILE, h, 0, 0, 32, h, false, false)` 只画底部 `h = (8-lv)*TILE/8` 像素（v 从纹理底部 0 起；液面即格子内的水平切口）。非流体仍画整格。

**11. `desktop/src/main/java/client/world/LocalPlayer.java`**
- 按 3.5 节加 `inWater` 判定与水中物理分支（放在 tick 的开头，影响 dx/重力/跳跃/冲刺）。

**12. `desktop/src/main/java/client/GdxGame.java`**
- `handleMessage` "state"：
  - chunks：`String lvStr = c.optString("lv", ""); byte[] lv = lvStr.isEmpty() ? null : Base64.getDecoder().decode(lvStr); world.putChunk(cx, cy, data, lv);`
  - tiles：`world.applyRemoteTile(t.optInt("x",0), t.optInt("y",0), t.optInt("type",0), t.optInt("lv",0));`
- `handlePlacing`：重排为「桶交互 → 普通方块（目标 AIR||液体）」。
- `handleBreaking`：破坏后 `world.setLocalTile(sel.x, sel.y, BlocksData.T_AIR, 0)`。
- `initDefaultInventory`：追加 `{"bucket", "1"}`。
- `drawItemIcon`：为 `bucket`/`water_bucket`/`lava_bucket` 加固定底色（灰/蓝/橙），提升辨识度。

### Web 前端
- **不改**。旧客户端忽略 `lv` 字段，行为与现状一致（水/岩浆仍整格半透明渲染、可穿行）。

## 五、假设与决策

1. 模拟位置：**服务器权威**（与"服务器权威存储/同步"架构一致），客户端只渲染 + 本地玩家物理。
2. 水位模型：**8 级**（用户已确认）。
3. 获取/放置：**水桶/岩浆桶**（用户已确认）；桶以纯名称字符串存在，不改 blocks_data.js（避免触碰生成数据），图标用色块+首字母（与现有非方块物品一致）。
4. 客户端范围：**仅桌面**（用户已确认）；Web 忽略新字段。
5. 初始背包加 1 个空桶（无合成系统，这是玩家获得桶的唯一途径）。
6. 岩浆不做伤害/燃烧（无血量框架）；不做"水推玩家"。
7. 天然海洋/岩浆湖全部视为 level 0 源：挖海底会持续灌水、海洋边缘会向岸上漫流最多 7 格（MC 同款行为，属预期）。
8. 一桶水 = 1 个 level 0 源：向两侧扩散 7 格后衰减；舀走源后残余流动水逐格消失（MC 一致）。
9. 化学反应默认做（圆石/黑曜石）；如需砍掉可在评审时说明。

## 六、验证步骤

1. **编译 core + server**：`javac -encoding UTF-8 -cp "lib\*" -d out/classes $(Get-ChildItem -Recurse core/src/main/java,server/src/main/java -Filter *.java | % FullName)`（排除 `gui\`、`GameScreen.java` 与 web 无关）。
2. **编译 desktop**：按项目记忆的 libGDX 完整 classpath 命令（含 `.m2` 中 gdx/lwjgl/natives-windows jar），`-d out/classes desktop/src/main/java/...`。
3. **运行**：`java -cp "$cp;desktop/assets" main.DesktopLauncher`（自动拉起后端）。
4. **用户实测**（按验证分工，由用户完成）：
   - 初始背包有 1 个空桶；
   - 对水/岩浆右键舀取 → 背包出现水桶/岩浆桶、原格变空气；
   - 倒水 → 下落、落地向两侧扩散、边缘逐级变薄、7 格后停止；舀走源 → 残余水衰减消失；
   - 挖海底 → 水自动灌入（源补给）；倒岩浆、再倒水 → 接触处生成圆石/黑曜石；
   - 往水里放方块 → 液体被替换；破坏水 → 变空气无掉落；
   - 入水 → 减速、空格上浮、无法二段跳/冲刺；
   - 重进世界 → 液面状态恢复（存档验证）。

## 七、风险与注意

- **字节溢出为既有 bug**（ID≥128 的方块如 deepslate 同步损坏）：level 用独立字节数组（`lv` 字段），不与类型字节冲突。
- **区块格式变化**：新存档多 256 个 level 值；旧档读取向后兼容。**注意**：已存在的旧存档区块文件不会被重写（level 全 0 = 满格源），行为与之前一致。
- **性能**：8Hz × ≤256 已加载区块 × 256 格 = 约 5 万格/步，纯 Java 常量操作，无压力。
- **边界区块**：液体到已加载边缘暂不流动，区块加载后自然续流。
- **客户端/服务器放置规则必须同步放宽**，否则客户端本地即时放置后会被服务器增量纠正（闪回）。
