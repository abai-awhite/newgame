# 实体系统设计与实现计划

## 1. 摘要

在 `core` 模块（纯逻辑，服务端权威实体）构建统一的实体系统：

- **实体基类 `Entity`**：所有实体继承，统一位置（中心坐标）、速度、**可配置/可动态调整的碰撞箱**、存活状态、标签集合。
- **标签系统**：实体基类内建 `addTag/removeTag/hasTag/getTags` API + `Tags` 常量类（标准标签），字符串格式、多标签共存、可扩展。
- **碰撞系统 `EntityPhysics`**：轴分离 AABB 方块碰撞（实体 vs 方块网格），实体独立固体判定（**非空气且非液体即实心**，不依赖 core Block 注册表），支撑被挖掉自然下落。
- **掉落物实体 `DropItem`**：继承 `Entity`，碰撞箱 16×16（与 16px 视觉图标一致），分配 `drop_item` 标签；物理（重力+方块碰撞）由碰撞系统驱动；**实体间碰撞响应 = 碰到玩家 → 被吸取**（服务器检测 AABB 重叠 → 发 `dropPickup` 事件 → 客户端入包；掉落物之间无碰撞）。

## 2. 现状分析（探索结论）

- 实体相关代码集中在 `core/src/main/java/entity/`：`AABB.java`（已有 `intersects`）、`DropItem.java`（现为手写 AABB 物理）、`Player.java`（原版客户端实体，完整物理）、`AutoJumpSystem.java`。
- `AABB`（`x/y/width/height` + `intersects`，含 EPSILON）可直接复用为碰撞盒。
- 方块查询：`InfiniteMap.getTileType(tx, ty)`（可能触发区块生成，碰撞扫描范围必须小——只扫碰撞盒覆盖的格子，O(1)）。
- core `Block` 注册表仅 Grass/Dirt/Stone 三种实心 → 实体用 `Block.isSolid` 会穿过沙/木/树叶。**决策：实体独立判定**（`Chunk.AIR/WATER/LAVA` 常量判断，`Chunk.SIZE=16`、`WORLD_HEIGHT=1024`）。
- 服务器 `WorldCore`：`dropItems: ConcurrentHashMap<Integer, DropItem>`，`tickDrops()` 由 `GameServer.tick()` 调用；`players: ConcurrentHashMap<String, PlayerProfile>`（权威坐标 `x/y`，左上角语义，碰撞盒 = inset 3 的 26×26）。
- **背包权威在客户端**：客户端磁吸拾取 → 上报 `pickup`（服务器移除掉落物）+ `inventory`（覆盖服务器 slots）。服务器直接改 slots 会与客户端上报冲突 → **决策：服务器检测碰撞后发 `dropPickup` 事件，入包仍在客户端**（复用现有拾取入包逻辑）。
- 客户端磁吸（150px）保留不动：服务器 AABB 重叠拾取与磁吸并存，服务器移除后客户端 `applyServerDrops` 同步消失，幂等无冲突。
- `core/entity/Player.java` 有 33 处 `currentX/currentY` 引用，可迁移到基类位置字段；`GameScreen.java` 不在编译范围（排除），Player 仅编译不运行，重构风险低。

## 3. 改动方案（按文件）

### 3.1 新增 `core/src/main/java/entity/Tags.java` —— 标签常量
```java
package entity;

/** 标准实体标签常量（字符串格式，可扩展自定义标签） */
public final class Tags {
    public static final String DROP_ITEM = "drop_item"; // 掉落物（用户需求："掉落物"标签）
    public static final String PLAYER    = "player";    // 玩家
    private Tags() {}
}
```

### 3.2 新增 `core/src/main/java/entity/Entity.java` —— 实体基类
- `interface Solidity { boolean isSolid(int tileType); }` 固体判定接口。
- `DEFAULT_SOLIDITY`：`type != Chunk.AIR && type != Chunk.WATER && type != Chunk.LAVA`（实体独立判定）。
- 字段：`protected final InfiniteMap map; protected final int tileSize;` 位置 `protected double x, y`（**中心坐标**）；速度 `protected double vx, vy`；`private boolean alive = true;` 碰撞箱 `private double collW, collH`（默认 = tileSize 满格）；`private final Set<String> tags = new HashSet<>();`
- 位置 API：`getX/getY/setX/setY/setPosition`。
- 碰撞箱 API（**可配置 + 动态调整**）：`setCollisionSize(w,h)`、`getCollisionWidth/Height`、`getAABB()`（`new AABB(x - collW/2, y - collH/2, collW, collH)`，中心语义）。
- 标签 API：`addTag(String)`、`removeTag(String): boolean`、`hasTag(String): boolean`、`getTags(): Set<String>`（unmodifiable）。
- 存活：`isAlive/setAlive`；速度：`getVX/getVY/setVX/setVY`；`getTileSize()`。
- `public abstract void update();` 每逻辑帧由实体系统驱动。

### 3.3 新增 `core/src/main/java/entity/EntityPhysics.java` —— 碰撞系统（方块碰撞）
```java
public final class EntityPhysics {
    public static class CollisionResult { public boolean hitX, hitY, onGround; }

    /** 轴分离移动 + 方块碰撞：先 X 后 Y，逐轴移动、扫碰撞盒覆盖的格子、实心方块吸附 */
    public static CollisionResult move(Entity e, double dx, double dy,
                                       Entity.Solidity solid, int worldHeightTiles)
}
```
- X 轴：`newX = x + dx`，构造临时碰撞盒，扫描覆盖格子（`floor` + EPSILON，越界 clamp），命中则吸附到方块侧边（`newX = tx*tsize ± collW/2`，`Math.round` 对齐）。
- Y 轴：同构；向下（vy>0）吸附到方块顶面（`newY = ty*tsize - collH/2`），向上吸附底面。
- `onGround`：移动后检查脚底（碰撞盒底部所在行）覆盖的列是否有实心方块。
- 复杂度：每实体每轴只扫碰撞盒覆盖的 1~3 个格子（O(1)），不会触发远处区块生成。

### 3.4 重构 `core/src/main/java/entity/DropItem.java` —— 掉落物实体
- `extends Entity`，构造 `super(map, tileSize, x, y)`（x/y 为中心坐标，与现有服务器广播/客户端渲染语义一致）。
- 构造器内：`setCollisionSize(16, 16)`（与 16px 视觉图标一致）；`addTag(Tags.DROP_ITEM)`。
- 常量：`MAX_LIFE_TICKS = 9600`（5 分钟，32Hz）、`GRAVITY = 1`、`MAX_FALL_SPEED = 16`。
- `update()`：寿命自增（超时 `setAlive(false)`）→ 重力（`vy += GRAVITY`，封顶）→ `EntityPhysics.move(this, 0, vy, DEFAULT_SOLIDITY, 1024)` → 落地（`hitY && vy>0` 时 `vy=0`、`grounded=true`）→ 世界边界 clamp。**支撑被挖掉后无碰撞 → 自然继续下落**。
- 保留 `getItemName/getCount/isGrounded`；移除自带的碰撞/地面检测代码（由 EntityPhysics 接管）。

### 3.5 重构 `core/src/main/java/entity/Player.java` —— 玩家接入实体基类
- `extends Entity`，构造调用 `super(map, tileSize, x, y)`，`setCollisionSize(26, 26)`（玩家 inset 3 碰撞盒，供实体间碰撞检测），`addTag(Tags.PLAYER)`。
- 将 33 处 `currentX/currentY` 引用迁移到基类 `x/y`（protected，同包可直接访问），删除重复字段声明。
- **自身物理算法（跳跃/冲刺/移动/轴分离碰撞）保持不变**，不强制改用 EntityPhysics（避免破坏已验证的行走/跨步/冲刺行为）；基类碰撞盒仅用于实体间碰撞检测。
- `GameScreen` 不在编译范围（排除），此改动仅编译验证。

### 3.6 服务器集成 `server/src/main/java/server/WorldCore.java`
- `spawnDrop`：`new DropItem(map, TILE_SIZE, dropX, dropY, itemName, 1)`（构造签名不变）。
- 新增拾取处理器接口：
```java
public interface DropPickupHandler {
    void onPickup(String playerId, int dropId, String itemName, int count);
}
```
- `tickDrops(DropPickupHandler handler)`：每实体 `update()` 后，若存活，遍历 `players.values()`，构造玩家碰撞盒 `new AABB(p.x + 3, p.y + 3, 26, 26)`（左上角 + inset 3），与 `d.getAABB()` `intersects` → 调 `handler.onPickup(...)` + `dropItems.remove(id)`（幂等），break。
- 复杂度：O(掉落物数 × 玩家数)，玩家数小，无性能问题。

### 3.7 服务器集成 `server/src/main/java/server/GameServer.java`
- `tick()` 中调用改为 `world.tickDrops(this::onDropPickup)`。
- `onDropPickup(playerId, dropId, itemName, count)`：找到玩家连接，发送：
```json
{"type":"dropPickup","id":<dropId>,"item":"<itemName>","count":1}
```

### 3.8 客户端处理拾取事件（桌面 + Web）
- `desktop/src/main/java/client/GdxGame.java`：`handleMessage` 新增 `case "dropPickup"` —— 从 `drops` 列表移除该 id（按 `id` 匹配 `DropView`）；调用现有本地拾取入包逻辑（磁吸完成时的同一函数）把 `itemName×count` 加入背包。
- `server/src/main/web/game.js`：同样处理 `dropPickup`（按 id 移除 serverDrops + 调用现有磁吸入包函数）。
- 现有磁吸、`pickup` 上报、`applyServerDrops` 不动（服务器已移除的掉落物自然消失，幂等）。

## 4. 假设与决策

1. **方块固体判定**：实体独立判定（非空气且非液体即实心），不改 core Block 注册表，不影响玩家现有物理（用户已确认）。
2. **实体间碰撞范围**：掉落物 vs 玩家（重叠 → 拾取事件）；掉落物之间无碰撞（用户已确认）；无"推开"逻辑。
3. **拾取实现**：服务器检测碰撞（权威）→ 发 `dropPickup` 事件 → 客户端入包；服务器不直接改玩家 slots（背包权威在客户端，避免冲突）。客户端磁吸保留。
4. **`Player` 继承基类**：满足"所有实体继承统一基类"，但物理算法保留（最小侵入）。
5. **桌面 `LocalPlayer` 不接入**：它是客户端本地传输移植（与服务器实体系统独立），强行继承 Entity 会破坏已验证物理，收益低。
6. **标签用英文常量**（`drop_item`/`player`），中文"掉落物"标签通过常量注释对应，可扩展自定义字符串标签。
7. 世界高度固定 1024 格；掉落物寿命 5 分钟（9600 tick）保持现状。

## 5. 验证步骤

1. 编译：`javac -encoding UTF-8 -cp "out/classes;lib/*" -d out/classes core/src/main/java/entity/*.java`（及依赖）→ 编译 server 全部 → 通过。
2. 静态检查：`node --check server/src/main/web/game.js`。
3. 运行验证（用户执行）：
   - **方块阻挡**：挖高处方块 → 掉落物落到地面（含沙/木/树叶上）停下，不穿方块；挖掉支撑 → 继续下落。
   - **标签识别**：服务器日志或调试验证掉落物带 `drop_item` 标签（可在 tickDrops 临时打印/或用 F3 类调试确认拾取事件触发）。
   - **碰到玩家被吸取**：掉落物静止后玩家走过去接触 → 立即入包消失；远处掉落物仍可磁吸。
   - **性能**：连续挖多块造成多个掉落物，无明显卡顿。

## 6. 风险与注意

- `getTileType` 会触发区块生成 → 碰撞扫描范围严格限制在碰撞盒覆盖的格子（已设计 O(1)）。
- 服务器 `dropItems` 为 ConcurrentHashMap，tickDrops 在协调线程（单线程 tick），遍历+移除安全。
- 客户端磁吸与服务器拾取并存：服务器拾取时掉落物已存在 → 客户端磁吸动画中断，可接受（符合"碰到即吸"）。
- `Player` 重构仅编译验证（GameScreen 排除），不影响运行中的桌面/Web 客户端。
