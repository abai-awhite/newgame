# 项目发展记忆（从过去到现在）

> 本文档按时间顺序记录 2D 仿 Minecraft 沙盒游戏从立项到当前的全部开发历程、关键决策与经验教训，供后续开发保持一致性与连续性。

## 一、项目概览（截至当前）

- **定位**：2D 横版多人沙盒游戏（仿 Minecraft）
- **架构**：Java 后端（WebSocket 权威存储/同步广播）+ 双客户端
  - **Web 前端**（HTML5 Canvas，`server/src/main/web/`，旧版保留）
  - **libGDX 桌面客户端**（`desktop/`，当前主力，2026-08-03 移植）
- **端口**：HTTP 静态页 :8080，WebSocket :8081
- **方块 ID**：Minecraft 1.13 扁平化数字 ID（stone=1、grass_block=8、dirt=9、water=32、lava=33、sand=34、oak_log=46、deepslate=1023 等）
- **服务器**：`server.ServerMain` 入口，桌面客户端 `DesktopLauncher` 检测 8081 未运行则自动拉起后端
- **编译**：`javac -encoding UTF-8 -cp "lib\*" -d out/classes`（core 排除 `gui\` 与 `GameScreen.java`；desktop 需 gdx/lwjgl classpath）
- **验证分工（用户偏好）**：所有实际验证（浏览器/跑游戏/可视化）由用户完成，助手只做代码修改与静态检查

## 二、开发时间线

### 阶段 1：Web 前端版（前后端一体，最早）

- 服务器只做权威存储、同步广播与少量逻辑；**大部分逻辑（玩家物理/交互/背包）在浏览器本地计算**
- 本地模拟 32Hz tick；玩家物理（移动/跳跃/二段跳/冲刺/自动跳跃 + AABB 碰撞）；DDA 射线选中/放置/破坏；45 槽背包（拖拽/右键分半/堆叠/数字键）
- 方块纹理**程序化绘制**（canvas + `prng(hash)` 确定性伪随机，按 ID 缓存 32×32）
- 玩家原图 7 张（`player/*.png`），方向映射：up/down/right/left 各 1 张 + 站立 4 帧
- 中文名翻译 `zhBlockName()`（CN_DIRECT 直接映射 + CN_WORDS 逐词拼装回退）
- 地形生成（core Chunk.generate）：`signedPow` 压缩噪声中间值（|raw|^1.7、振幅 110）使大部分区域平缓；群系低频噪声成片分布（平原/森林/沙漠/雪原，高地形强制山地）

### 阶段 2：Web 版功能迭代

- **方块纹理细节重绘**；地图生成树 + 平原/山脉平衡
- **快捷栏切换提示**（5 秒淡出）
- **背包悬停详情**（后改为悬停立即显示，去掉 2.5s 延迟）
- **损坏图标修复**（ITEM_TILE 放宽 + itemIconUrl 兜底）
- **天气系统整体删除**（服务端 `WeatherSystem.java`、配置、客户端渲染全移除；仅剩 `weathered_*` 方块名与天气无关）——git 提交 b05cc36
- **背包面板重排为三栏**：左侧玩家形象 + 盔甲槽（纯界面无逻辑）、中间 9×5 网格、右侧 3×3 合成格（仅界面无合成逻辑）+ 方块详情横排

### 阶段 3：libGDX 桌面客户端移植（2026-08-03）

- 架构：libGDX 1.12.1 + LWJGL3，**本地物理/交互/背包在客户端，服务器权威存储/广播**（协议与 Web 版一致）；Web 版保留不删
- 源码：`desktop/src/main/java/`
  - `main/DesktopLauncher`：检测 8081，未运行则以子进程拉起 `server.ServerMain`（等 20s）；窗口 1280×720
  - `client/GdxGame`：主类（约 2000 行），移植 game.js 全部逻辑
  - `world/LocalPlayer`（物理 32Hz）、`world/ClientWorld`（区块缓存）、`net/NetClient`（Java-WebSocket，回调入队+渲染线程 drain）、`data/BlocksData`、`data/ZhName`、`render/TextureFactory`（程序化纹理，mulberry32 与 JS 一致）、`render/WorldRenderer`、`render/PlayerTextures`、`ui/UiKit`（字体/按钮/文本框）、`ClientPrefs`
- **字体（双字体混排）**：英文/数字 Comic Sans MS（comic.ttf），中文潮小社小作文简体（chaoxiaoshe.ttf）
  - **坑 1**：FreeType 默认只生成 ASCII → 中文全口口口
  - **坑 2**：`p.incremental=true` 在 JDK25 下 gdx-freetype64.dll 原生崩溃 → 必须预生成 `characters = DEFAULT_CHARS + ZhName.allChars() + UI_CHARS`
  - **坑 3**：新增中文字符串需同步补进 UiKit.UI_CHARS
  - **坑 4**：合成区箭头"→"两字体缺字形 → 改为矩形手动绘制
- **输入坐标坑**：libGDX 输入 y 顶端为 0 向下（与 UI 一致），之前 `vh - sy` 翻转导致点击 y 轴颠倒 → 已删除翻转
- **移植中的其它坑**：`id * 2654435761` int 溢出 → 用 `(int)(id * 2654435761L)`；GdxGame 字段初始化器调 ClientPrefs（Gdx.app 未设置）NPE → 开关移入 create()；`loadKeyBinds()` 未调用 → create() 中调用；`setWindowIcon` 资源缺失崩溃 → 加存在性判断

8. **二次创建后无法移动修复**：点过输入框后 `focusedField` 残留吞掉移动按键 → 进入游戏时重置 focusedField/listeningAction
9. **掉落物物理（从手写到实体系统，三次演进）**：
   - 初版：掉落物完全无物理（坐标固定悬浮）→ 加手写重力 + findGroundY 单向碰撞（10s 消失）
   - 支撑移除继续下落 + 消失时间 5 分钟（9600 tick）
   - 用户质疑"掉落物作为实体才有物理系统" → **实体系统**（见下）
10. **实体系统（核心架构，2026-08-03）**：
    - `core/entity/Entity.java`：实体基类（中心坐标/速度/可配置碰撞箱/标签 API addTag/removeTag/hasTag/getTags/存活）
    - `core/entity/Tags.java`：标准标签常量（`drop_item` 掉落物、`player` 玩家）
    - `core/entity/EntityPhysics.java`：轴分离 AABB 方块碰撞，实体独立固体判定（**非空气且非液体即实心**，不依赖 Block 注册表——注册表只有 3 种）
    - `core/entity/DropItem.java`：继承 Entity，16×16 碰撞箱（与视觉一致），标签 drop_item
    - `core/entity/Player.java`：继承 Entity（位置字段迁移到基类，物理保留）
    - 服务器 WorldCore.tickDrops：实体物理 + **实体间碰撞**（掉落物与玩家 AABB 重叠 → dropPickup 事件 → 客户端入包，背包权威在客户端）
11. **移除客户端远程磁吸**（用户反馈"吸取范围太大、吸取不遵守物理"）：掉落物完全由服务器物理驱动，玩家碰到（AABB 重叠）才被吸取
12. **Q 扔出物品（类 Minecraft，最新）**：
    - 按键 Q（可绑定）：消耗当前快捷栏手持物品 1 个，客户端减背包 + 上报 `throw` 消息
    - 服务器 `WorldCore.spawnDropForPlayer`：从玩家中心朝面向方向生成掉落物，带水平初速度（vx=dir*6, vy=-5）
    - DropItem 物理支持水平速度（空中阻尼 0.9、落地停止水平）

## 三、关键架构决策

1. **背包权威在客户端**：客户端磁吸/合成/使用逻辑本地算，上报整个背包；服务器只存储 slots + 移除掉落物。服务器直接改 slots 会与客户端上报冲突。
2. **实体系统放在 core（纯逻辑）**：服务器权威实体（掉落物）用统一 Entity/EntityPhysics；桌面 LocalPlayer 是客户端本地传输移植，不接入实体系统（避免破坏已验证物理）。
3. **实体方块固体判定独立于 Block 注册表**：core Block 只有石头/草/泥土三种实心，实体用"非空气非液体"判定可与沙/木/树叶正确碰撞；不改变玩家现有物理行为。
4. **拾取实现**：服务器检测 AABB 重叠（权威）→ 发 `dropPickup` 事件 → 客户端入包（复用磁吸入包逻辑）；掉落物之间无碰撞（用户确认）。
5. **树/地形生成结构模板化**：10 种树结构（字符模板 T=树干/L=树叶）在地形生成最后阶段逐格复制，森林/平原/雪原/沙漠按群系挑选；密度可调（阈值越低越密）。
6. **渲染保持 libGDX/OpenGL**：评估过改 Vulkan——libGDX 官方无 Vulkan 后端，需脱离渲染层自写 LWJGL3+Vulkan 渲染器（对 2D 游戏无收益、工程量大），用户确认保持现状。

## 四、经验教训（重要，勿重蹈）

- **Web 静态文件从 `server/src/main/web` 磁盘读取**，修改后立即生效，无需重启服务器；**Java 后端改动必须重编译 + 重启才生效**
- **树不生成的坑**：横版地图中地表高度在本区块内是 `localGy = gy - chunkY*SIZE`，绝不能取 `tiles[localX][0]`（那是区块顶部，几乎永远是空气）
- **玩家朝向映射以原版 Java Player.java 为准**：up→player-up-1、down→player-down-1、right→player-r-1、left→player-l-1；站立 1→player-1、2→player-2、3→player-3、4→player-2
- **自动跨步**：抬升用 `ty*TILE - inset - colH` 而非整格；地面检测多列；净空只查 (tx, ty-1)
- **libGDX 输入 y 不要翻转**（顶端为 0 与 UI 一致）
- **FreeType 必须预生成字符**（incremental 在 JDK25 崩溃）；新增中文记得补 UI_CHARS
- **杀进程用命令行匹配 `DesktopLauncher|ServerMain`**，避免误杀 IDE 的 JDT 语言服务器
- **掉落物渲染语义**：客户端把 (x,y) 当 16px 图标中心；实体物理内部用中心坐标，碰撞盒从中心派生（落地后图标底贴方块顶面）
- **磁吸教训**：远程磁吸与"碰到才吸"需求冲突 → 最终方案为服务器 AABB 碰撞拾取 + 无客户端磁吸
